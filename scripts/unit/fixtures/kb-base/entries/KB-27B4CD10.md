The Active column on /company/members is bound to the CONTACT record's status, not to the
underlying security account. Locking the account through the Admin SPA leaves the contact
untouched, so the storefront keeps rendering Active while sign-in is already refused.

Query.organizationContacts returns both fields; the storefront reads only the first.
