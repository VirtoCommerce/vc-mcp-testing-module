01The bug

Every value cell in the compare table is a flex item with overflow-wrap: break-word and no min-w-0. break-word does not reduce a box's min-content width, so a long unbroken token (a 32-char hex SKU code) kept its full intrinsic width regardless of the cell's max-width and was painted outside the cell, across the next column. At 390px the neighbour's value was drawn entirely inside it — both unreadable, nothing scrollable to recover either.

Fix (CSS only, one rule) — .compare-table__row-value: overflow-wrap: break-word → overflow-wrap: anywhere, which does reduce min-content width, so the value wraps inside its own column.

The pre-fix build itself can't be run against this catalog, so the shipped rule was toggled back to break-word live on the SKU cells, re-measured, then restored. 07Notes & residual risk

Fix is CSS-only and class-wide — covers all 7 rows, not just SKU. Any future long unbroken value in brand, original_sku, Manufacture, etc. is covered by the same rule.
Single-layered defence. The cell still has overflow: visible and no min-w-0. anywhere removes the cause rather than adding a clip fallback — not reachable with current catalog data (next-longest code is 11 chars), so this is an observation, not a defect.
Verified on Chromium only. A Firefox/Edge spot-check would close that cheaply.
