VcScheduler: an all-day event with End = Start saved into the void

VERIFIED STR 3/3 · checklist 12/12

The defect

Creating an all-day event whose End equalled its Start saved without complaint, then rendered nowhere and could not be reached by mouse or keyboard — no chip in any day cell, no event button in the accessibility tree, no error, toast or field message. The only visible sign was the empty state disappearing.

Root cause, confirmed in source: all-day spans store an exclusive end — midnight of the day after the last covered day. The editor bound the raw stored end straight to its End field, so “the same day as Start” was a zero-length range that laid out to nothing.

Fix under test

PR #351 took the inclusive-field option: endFieldValue displays the last covered day, setEnd converts back to the exclusive boundary on save, and the all-day exemption left the validity check — so an End before Start is now refused too, a case absent from the original report.

Evidence

Findings not filed

All four are pre-existing and unrelated to this fix, so none is a side effect of it.

  • Timed chip time-format mismatch. Visible label is 24-hour (00:00), accessible name is 12-hour (12:00 AM) — sighted and screen-reader users get different notations for the same value.
  • End-before-Start refusal is silent. Save simply disables with no reason given. This satisfies the documented “refused rather than saved” contract, and a disabled control is validation working — a team judgment call rather than a defect.
  • Datepicker does not auto-close on selection. The overlay stays open and intercepts pointer events, so Save is unclickable until Escape or an outside click. Affects Start and End; pre-existing vc-datepicker behaviour.
  • Storybook story-meta defect. Control of type color only supports string, received "boolean" on every load — an argTypes mismatch in the story configuration, not the component.
Oracle substitution. vc-shell is a separate product from the Virto storefront: no BL-*, BL-UI-*, ECL-*, critical-ui-scope or storefront-selectors entry covers it, and no regression suite exercises it. The component’s own vc-scheduler.docs.md contract at main was used as the correctness oracle; elements were located by role and accessible name.
Instruments. Playwright accessibility snapshot; browser_evaluate is blocked by the real-user hook and was never attempted. No assistive-technology pass was run — this was a11y-tree and behaviour verification, not screen-reader coverage.
