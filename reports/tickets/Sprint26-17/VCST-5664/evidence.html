The defect

With stateKey set, the composable restored the page number via setPage, which by design does not fire onPageChange — correct, since a restore should not double-load. But the consumer was never told a restore happened, so an unconditional first load at skip: 0 left the paginator on page N showing page 1’s rows: no error, no warning, and clicking page N is a no-op because it is already active.

Root cause addressed, not the symptom: the composable now returns restoredPage, giving the consumer the signal it lacked. A missing TableQueryState provider now warns instead of silently disabling the feature, and assigning to currentPage is deprecated.
