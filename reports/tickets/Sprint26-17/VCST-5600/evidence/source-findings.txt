[1] RESIZE IS GATED ON A PROP THAT DEFAULTS TO FALSE
  GridstackDashboard.vue:192   resizable: false        (default)
  DraggableDashboard.vue:39    resizable: false        (default)
  GridstackDashboard.vue:370   if (props.resizable) resizeWidgetBy(widget, dx, dy);
  The prop is set by the CONSUMING app (Vendor Portal), which is a DIFFERENT
  repo -- so it cannot be established statically from vc-shell. Evidence it is
  enabled on vcmp-dev: the ticket's own 2026-07-29 description observed "5
  resize handles" live, and the 08-04 pass drove Shift+Right from w=6 to 7.
  Consequence for this run: an inert Shift+arrow would be CORRECT behaviour
  under resizable=false, not a defect -- so it must be reported BLOCKED, never
  FAIL. The agent was instructed accordingly mid-run.

[2] EVERY ANNOUNCEMENT AND LABEL IS HARDCODED ENGLISH -- NOT LOCALIZED

[3] THE RESIZE AFFORDANCE IS UNDISCOVERABLE
  No user-facing string anywhere mentions Shift+arrow or resizing. Every
  instruction string enumerates only move/drop/cancel:
    "Picked up. Arrow keys move, Enter drops, Escape cancels."   <- no resize
    "Press Enter to pick up and rearrange with the arrow keys."  <- no resize
  Shift+arrow is documented ONLY in the developer file
  draggable-dashboard.docs.md:152. So a keyboard-only or screen-reader user is
  handed an explicit key list that OMITS the resize capability -- they can only
  find it by guessing. The ticket's AC1 requires widgets be "reordered AND
  resized without a pointer"; the capability exists but is unannounced.
  Not a 2.5.7 failure (an alternative does exist); closer to 3.3.2 Labels or
  Instructions, and plainly a usability gap. Low severity.

[3] IS RETRACTED — "the resize affordance is undiscoverable" was WRONG.
  The live run captured the pickup announcement:
    "Last products picked up. Use arrow keys to move, Shift and arrow keys to
     resize, Enter to drop, Escape to cancel."
  Source confirms it at GridstackDashboard.vue:281-283 -- a multi-line BACKTICK
  template literal. My grep pattern '"[^"]{15,}"' matched only single-line
  double-quoted strings, so it never saw that string and I concluded resize was
  announced nowhere. It IS announced, at exactly the moment it becomes usable.
  What survives, much weaker: the grabbed-state ARIA-LABEL (:381) still reads
  "Picked up. Arrow keys move, Enter drops, Escape cancels." -- omitting resize,
  so the label and the announcement disagree. A cosmetic inconsistency, not a
  discoverability failure. Not worth filing on its own.

[4] IS SHARPENED — no test was removed, and the rationale for not adding one
    is refuted by live evidence.
  #303's message says "A test that asserted otherwise [Escape restoring
  displaced neighbours] was modelling its own one-way mock and has been
  removed." Checked: `git show` on both merged commits (c607552f6, 761e2ac35)
  removes NO `it(`, and `git log --all -S displaced` over the dashboard tree
  returns nothing. A squash-merge could hide churn within the branch, so the
  fair conclusion is that NO COVERAGE WAS LOST relative to what shipped before.
  The important part is the RATIONALE, which live testing refutes. #303 states:
    "Escape restoring displaced neighbours [not changed]. Real gridstack
     compaction is reversible -- moving a widget back pulls the others with it,
     verified live across five widgets -- so no extra layout snapshot is
     needed."
  Live run, single pickup: offers (0,3) -> Enter -> ArrowUp -> offers (0,0) with
  products pushed to (0,6) -> Escape -> DOM STAYS at offers (0,0) / products
  (0,6), while the live region announces "Move cancelled. Offers returned to
  its original position and size." Compaction is NOT reversible here. The
  decision not to snapshot the layout rests on a premise that does not hold.
  (localStorage still holds the pre-pickup layout, so nothing is corrupted and
  a reload repairs the view -- this is a correctness-of-feedback bug, not data
  loss.) => Bug 1 in the report.
