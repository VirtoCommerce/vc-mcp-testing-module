Fix verification · VCST-5554 · 2026-08-03

A mistyped setting row no longer takes down the Orders dashboard

Verified · STR 3/3

GET /api/order/dashboardStatistics returned 500 for every operator because one persisted setting row was stored as a string under a boolean descriptor. The platform now treats the registered descriptor as the authority on a setting's type, so the same drifted row is tolerated instead of thrown on.

Root cause

SettingValueEntity.GetValue() reads whichever column the stored ValueType points at. For Order.DashboardStatistics.Enable that column was ShortTextValue holding the string "True", while the Orders module declares the setting Boolean. GetValueInternalAsync<T> then did an unguarded (T)value cast. The synchronous sibling already used Convert.ChangeType; the async path — the one GetValueAsync<bool> takes — was the inconsistent one.

The trigger was environment data drift (a restored database), which is why the same build served 200 on vcptcore-qa. The defect it exposed is that the read path trusted the persisted ValueType column over the registered descriptor.

Stored-state matrix

One green result proves little on its own — with no drifted row present the endpoint returns 200 on either build. These four stored states were each written and probed live, and together they rule that out.

Stored row Descriptor Read resolves to Endpoint What it establishes
drift ShortText "True" Boolean true 200 3/3 The exact original corruption. Pre-fix this threw InvalidCastException.
drift ShortText "yes" Boolean true (descriptor default) 200 Unconvertible input falls back to DefaultValue rather than throwing. Also proves the row really is ShortText: a Boolean write of "yes" would have thrown at save, yet the POST returned 204.
drift ShortText "False" Boolean false 200 disabled path Response collapses to revenue: null. The stored string is genuinely read and converted — so none of these writes was a silent no-op.
ok Boolean true Boolean true 200 3/3 Restored end state. Environment returned to its exact pre-test baseline.

A second read corroborates the coercion directly rather than by absence of a symptom: GET /api/platform/settings/v2/global/values returned "Order.DashboardStatistics.Enable": true as a JSON boolean while the persisted row was still ShortText / "True".
