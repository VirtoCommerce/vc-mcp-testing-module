# Manage Organization Memberships

An **Organization Membership** is a single record that ties one contact (user) to one organization and stores
that user's roles within that organization plus a per-organization locked/unlocked state. It lives in the
**Contacts** module (also called the Customer module). Before this feature, a user had one global set of
roles across every organization they belonged to; with organization memberships each organization carries its
own independent role set and lock state.

## Overview / Key features

- **Membership visibility** — view all organizations a contact belongs to, with the assigned roles and lock
  state for each, from a single widget in the contact blade.
- **Per-organization role assignment** — change a user's roles inside one organization without affecting
  their roles in any other organization.
- **Per-organization lock / unlock** — block a user's access to one organization immediately (revokes their
  active session for that org) without disabling their global account or access to other organizations.
- **Timed lock** — optionally set a lock expiry date/time so the block lifts automatically.

!!! note
    The **Organization memberships** widget and blade are delivered by vc-module-customer PR #300.
    The widget is deployed on this environment (verified 2026-06-19). No back-filled membership records
    exist yet for existing contacts; the widget shows **0** until memberships are created or migrated.

## View a contact's organization memberships

To view all organizations a contact belongs to and inspect their roles and status in each:

1. Click **Contacts** in the main menu.

   ![Companies and contacts blade](../../reports/bugs/screenshots/VCST-5028-contacts-blade.png)
   *The **Companies and contacts** blade opens, listing all contacts and organizations (647 records on this environment).*

2. In the **Companies and contacts** blade, type the contact's name in the **Search keyword...** field and
   press **Enter**.

3. In the filtered list, click the contact's name row to open the **Contact detail** blade.

   ![Emily Johnson contact detail blade](../../reports/bugs/screenshots/VCST-5028-emily-contact-blade.png)
   *The contact detail blade shows widgets for Accounts, Organization memberships, Addresses, Emails, Orders, and others. The **Organization memberships** widget displays the membership count.*

4. Click the **Organization memberships** widget.

   ![Organization memberships blade — empty](../../reports/bugs/screenshots/VCST-5028-memberships-blade-open.png)
   *The **Organization memberships** blade opens to the right, showing a list of all the contact's
   organization memberships. Columns: **Organization**, **Roles**, **Status**.*

The blade toolbar contains **Refresh**, **Add**, and **Delete** actions.

!!! tip
    The count shown on the widget (e.g. **0**, **3**) reflects the number of membership records for this
    contact. A contact that belongs to multiple organizations will have one row per organization in this list.

## Add an organization membership

To assign a contact to an organization and set their initial roles:

1. Open the contact's **Organization memberships** blade (steps 1–4 above).

2. Click **Add** in the blade toolbar.

   The **New membership** blade opens.

   ![New membership blade with Save, Reset, Lock, Unlock toolbar buttons](../../reports/bugs/screenshots/VCST-5028-new-membership-blade.png)
   *The **New membership** blade. Toolbar buttons: **Save**, **Reset**, **Lock**, **Unlock**.*

3. In the **New membership** blade, fill in the following fields:

   | Field | Description | Example |
   |-------|-------------|---------|
   | **Organization** | The organization to assign this contact to. Select from the dropdown. | `AGENT-TEST-Org-TechFlow-20260310` |
   | **Roles** | One or more platform roles for this contact within the selected organization. Click **Add** to open the role picker. | `Organization Maintainer` |
   | **Status** | Read-only display — reflects whether the membership is **Active** or **Locked**. Set via the **Lock** / **Unlock** toolbar buttons. | `Active` |

4. Click **Save** in the toolbar.

The membership record is created. The **Organization memberships** widget count on the contact blade
increments by one.

!!! note
    **Roles are org-scoped.** The roles you assign here apply only to this organization. The contact's
    roles in any other organization remain unchanged. Roles assigned through the global **Accounts** widget
    apply across all organizations (legacy behavior); roles set in the **Organization memberships** blade
    are per-org overrides.

## Change a contact's roles in one organization

To update which roles a contact holds within a specific organization (without affecting other organizations):

1. Open the contact's **Organization memberships** blade.
2. Click the membership row for the organization you want to edit.
3. In the membership detail blade, click the current role in the **Roles** list to remove it, or click
   **Add** to assign additional roles.
4. Click **Save** in the toolbar.

The role change applies only to that organization. The contact's JWT (access token) will reflect the updated
org-scoped permissions the next time they authenticate into that organization.

!!! note
    **Token refresh.** A role change takes effect at the contact's next login to that organization. Active
    sessions are not revoked by a role change alone — only a **Lock** action revokes active sessions
    immediately.

## Lock (block) a contact in one organization

Locking a contact in an organization immediately revokes their active sessions for that org and prevents
them from authenticating into it. Their global account and their access to other organizations are
unaffected.

To lock a contact in one organization:

1. Open the contact's **Organization memberships** blade.
2. Click the membership row for the organization you want to block the contact from.
3. In the membership detail blade, click **Lock** in the toolbar.
4. Optionally, set a **Lock expiry date/time** if the lock should lift automatically.

   !!! note "Timed lock support"
       The REST endpoint (`POST /api/customer/organization-memberships/{id}/lock`) accepts an optional
       `lockoutEnd` date. Whether the Admin blade exposes a date picker for this field is subject to live
       verification — the field may appear only in specific versions of the module.

5. Confirm the lock. The **Status** column in the memberships list updates to **Locked**.

The contact's active sessions for that organization are revoked immediately. If they attempt to sign in to
that organization while locked, they see the error:

> *"Your access to organization '…' has been blocked. Please contact your organization administrator."*

!!! warning
    **Org lock is independent of global account lockout.** Locking a contact in one organization does
    NOT disable their platform account. They can still sign in to other organizations they belong to and
    to the Admin back-office. To block all access platform-wide, use the **Security** module to disable
    the user's account.

#### Precedence at sign-in

| Condition | Outcome |
|-----------|---------|
| Global account locked (`ApplicationUser.LockoutEnd > now`) | Sign-in blocked entirely (highest priority) |
| Organization membership locked (`IsLocked = true`) while signing in to that org | Sign-in to that org blocked; other orgs unaffected |
| No global lock, no org lock | Normal sign-in |

---

## Unlock a contact in one organization

To restore a previously locked contact's access to one organization:

1. Open the contact's **Organization memberships** blade.
2. Click the membership row for the organization you want to unlock.
3. In the membership detail blade, click **Unlock** in the toolbar.
4. Click **Save** in the toolbar.

The **Status** column returns to **Active**. The contact can sign in to that organization again at their
next authentication attempt.

---

## Delete an organization membership

To remove a contact's membership from an organization entirely (removes their roles and access for that org):

1. Open the contact's **Organization memberships** blade.
2. Select the checkbox on the membership row you want to remove.
3. Click **Delete** in the blade toolbar.

!!! warning
    Deleting a membership is permanent. The contact loses all org-scoped roles and access for that
    organization. Re-adding them later requires creating a new membership and re-assigning roles.

---

## Bulk lock from the contacts list

You can lock one or more contacts in an organization directly from the **Companies and contacts** list
without opening individual contact blades:

1. Click **Contacts** in the main menu.
2. In the **Companies and contacts** blade, select the checkboxes next to the contacts you want to lock.
3. Click **Lock in organization** in the toolbar.

!!! note
    The **Lock in organization** toolbar action is available on this environment (visible in the
    **Companies and contacts** blade toolbar). It applies the org lock to all selected contacts for
    the organization context currently in scope.

## Required permissions

To perform any of the actions above, the operator's platform role must include the following permissions.
Assign these in **Security** → **Roles** → the operator's role → **Permissions**:

| Permission | Grants |
|------------|--------|
| `customer:organization-membership:read` | View the **Organization memberships** widget and list |
| `customer:organization-membership:create` | Add a new membership (the **Add** action) |
| `customer:organization-membership:update` | Edit roles, lock, and unlock |
| `customer:organization-membership:delete` | Remove a membership (the **Delete** action) |

!!! tip
    An operator who only needs read-only visibility (support triage) requires only the **read** permission.
    Full membership management requires all four permissions.

## Known limitations (as of 2026-06-19)

| Limitation | Impact |
|------------|--------|
| No migration of pre-existing org members | Contacts assigned to organizations before this feature was deployed have **0** membership records. They must be back-filled manually via **Add**, or via the REST API (`POST /api/customer/organization-memberships`). |
| REST `POST /` lacks input validation (BUG-B, open) | Submitting a membership without a `userId` returns HTTP 500 with a DB error. Use the Admin blade — it pre-populates the user ID from the contact context. Do not use raw API calls without a valid `userId`. |
| xAPI lock has no timed-lock parity | The storefront GraphQL `lockOrganizationContact` mutation locks immediately with no expiry. Timed locks are only configurable via the Admin blade or the REST lock endpoint. |
