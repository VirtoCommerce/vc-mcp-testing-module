## Contract (pinned, live-verified)
- **Endpoint:** `POST {{BACK_URL}}graphql/sales-rep` (scoped schema; GraphiQL `{{BACK_URL}}ui/graphiql/sales-rep`).
- **Auth:** OAuth2 password grant **with a `storeId` form param** — omitting it fails `400 invalid_grant`.
- **Caller org** from the `organization_id` token claim — **no org argument**. Args: `first, after, keyword, sort, storeId`. Item fields: `id, firstName, lastName, middleName, fullName, name, about, photoUrl, emails, phones`.
- **Scoping:** active-only (blocked account / per-org-locked membership / cross-org all excluded); anonymous → auth error; `storeId` null = all stores; `keyword` = case-insensitive name substring.

## Anomalies observed (live capture — reported, none filed)
1. **vcptcore-qa admin Home dashboard is effectively unclickable** — two broken chart widgets ("Not enough columns given to draw the requested chart.") appear to drive a continuous re-render that blocked *all* clicks under Firefox automation (had to switch to Edge). Worth a real-browser regression check — may affect genuine operators.
2. **`photoUrl` has no admin control.** The rep edit blade has no photo/avatar field, so `photoUrl` is generally `null`. Documented as a fallback-avatar note (dev) and omitted from the admin doc.
3. **"Blocked" list column label reads backwards** — the status icon is labelled "Active" when the rep *is* blocked. Called out precisely in the admin doc; source of truth is the Block/Unblock toolbar button.
4. **Sales Rep app is partially built** — the "Organizations", "Blocked Sales Reps", "Not assigned …" dashboard tiles route to "This view is coming soon." placeholders. Only the Sales Reps list + edit blade are functional. Docs describe only the working surface.
5. **`sort` field component ignored** (QA observation on the query): only the direction applies; `:asc` variants return creation order. Documented as a known limitation.
