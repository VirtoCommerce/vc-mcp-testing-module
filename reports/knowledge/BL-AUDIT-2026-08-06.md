## Not applied → `reports/ba/bl-proposals-2026-08-06.md`

Proposed sharpening of BL-PRICE-005 from one conflated sentence into a **per-surface** contract, because the current wording ("products … disappear **or** show 'Unavailable'") passes under either outcome and therefore cannot detect the defect that exists:

| Surface | Observed | Correct? |
|---|---|---|
| Listing / search | hidden | yes |
| Cart | blocked | yes |
| PDP (direct nav) | **`€0.00`** | **no** — matches its own violation signal |

Key evidence: xAPI `products(currencyCode:"EUR", query:"laptop")` returns `totalCount=149` — identical to USD — with all EUR rows at `price.list.amount = 0`; and the UI-kit atom guards `value?.formattedAmount ?? "N/A"`, i.e. **nullish-only**, so a zero-amount Money bypasses it. The theme cannot render "unavailable" while the API returns `0`.

Carried to the proposals file as open questions, deliberately **not** decided here: whether the intended API contract is `null` or an always-present Money (this changes which side owns the fix), and by what mechanism listing/search hides unpriced products (xAPI returns all 149; the storefront shows none — client-side filter vs a differently-filtered query is unestablished).
