## What the source shows

- **Round trip preserves configuration** — `SavedForLaterListService.CopyConfiguredItemsAsync` (`:144`)
  rebuilds each configured item through `ConfiguredLineItemContainer` on both legs: Text keeps
  `customText`, Product/Variation re-resolve their product, File re-attaches its files. Landed in
  `9fe8d07` (VCST-4205, 2026-05-20); before that the configuration was not carried.
- **Active cart displays it** — `fullLineItem.graphql:42` selects `configurationItems`, and both move
  mutations return `cart { ...fullCart }`.
- **Saved-for-Later card cannot display it** — `savedForLaterLineItem.graphql` selects no
  `configurationItems`. This is the "not implemented" display gap, a different surface from BL-CART-015.
- **Conditions the rule does not state** (`SavedForLaterListService.cs`):
  - a Product/Variation section whose product does not resolve for the target cart is skipped (`:215`);
  - files are copied only when owned by the source cart (`:267`);
  - if the configurable product itself does not resolve, the item is not re-added (`:163`) **but is still
    removed from the source list** (`:123`) — the whole line is lost. Not live-reproduced; see proposals.

## Resolution of the CART-070 contradiction

2026-07-27 (its `References` column) to assert only the round trip — configuration in the active cart
before Save-for-Later and again after Move-to-cart — with the Saved-for-Later card display assertion
deferred. That remaining scope is exactly what BL-CART-015 states and the source implements. The
registry entry (`addedOn 2026-08-06`, `source: memory:…`) still describes the pre-re-scope case, so it
would label a genuine BL-CART-015 regression as non-actionable. Proposed removal — not done here (this
command writes only the oracle).
