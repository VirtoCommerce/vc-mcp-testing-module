### ⚠ Docs ↔ source contradiction — candidate 1, the substantive finding of this pass

`IsOrderSent` (`vc-module-order` `SendNotificationsOrderChangedEventHandler.cs` :233-238) returns
`oldSentShipmentsCount == 0 && newSentShipmentsCount > 0` — it counts shipments in a `Send`/`Sent` state and
fires on the **zero→non-zero** transition, with **no comparison against the ordered items**. On a
multi-shipment order the **first** shipment therefore sends the customer's "order shipped" email, while the
PlatformUserGuide promises it "when **all** ordered items have been shipped". The sibling `IsOrderPaid`
(:221-226) *does* aggregate properly (`NewEntry.Total <= newPaidTotal`), making the shipment half read as
oversight rather than intent; the no-duplicate half holds only incidentally via the `old == 0` latch, not a
completion test. **Route to a human/tracker decision** — the draft's `Rule` is deliberately written to the
**documented** contract, so promoting it later makes the current code a detectable violation. Secondary:
`oldPaidTotal != newPaidTotal` lets an extra paid payment on a paid order re-fire the order-paid email.

### Decisions and corrections (full reasoning in the proposals file)

- **Both fold-in questions resolved as new IDs.** Candidate 2 is *not* an amendment to `BL-NOTIF-001` (001 is
  scoped to the *order confirmation* email and *once-only* delivery; candidate 2 is a cross-type record-shape
  contract — folding in would let a P1 order-email rule govern password-reset notifications). Candidate 5 is
  *not* a clause on `BL-NOTIF-005` (005 owns the predefined edit→override→restore lifecycle; 5 is removal,
  protecting the **default-language** template — a class 005 never mentions).
- **Two candidate rules were wrong; the drafts carry corrected text.** Candidate 4: the cron is **global-only**
  (`StoreSettings` exposes only the enable flag and idle-hours threshold) — what varies per store is
  *participation* and the *abandonment threshold*, not the schedule. Candidate 2: retries occur *within* a
  dispatch and an already-errored record is refused on re-enqueue (:77-81), so the draft asserts attempt-count
  evidence, not a post-hoc retry guarantee — settle before promotion, 058 depends on it. Also worth filing
  separately: the template-deletion restriction (candidate 5) is undocumented.
