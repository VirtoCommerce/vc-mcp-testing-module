## Findings
**O1 revoke is absent, and the tool that looks like one isn't.** None of the 19 advertised operations
revokes; `DELETE /ucp/v1/internal/handoff/{tok}`, `…/revoke`, `…/cancel`, `DELETE /ucp/v1/handoff/{tok}`,
`…/invalidate` all 404. `logout_buyer` takes an **empty argument schema** and returns `logged_out:true` plus
prose telling the *model* to stop using the identifiers; a handoff minted before it still restored **200**.
**O2 expired ≡ consumed ≡ forged (Sc.20, settled).** A genuinely TTL-expired token (probed 42 s past
`expires_at`) and a never-existed one both return 400 with **equal `code`, `message`, `details`, key set**:
`{"code":"invalid_request","message":"ucp_session is invalid or expired.","details":{}}`. Only
`correlation_id` differs and carries no cause; `details` is the natural carrier and is empty. Buyer-side one
banner conflates all three *by wording*: "…has expired, has already been used, or is unavailable in this
tab." **Not distinguishable from either side.**
**O3 anonymous handoffs are bearer-only; authenticated ones are identity-bound.** Anonymous restore of an
*authed* handoff → `401 identity_required`; a second org buyer restoring another's → `403
buyer_context_mismatch` (server-side, her own bearer). But a signed-in buyer opening an *anonymous* handoff
gets **200** and lands on `/cart/7fbd7d9b…` — neither the minted cart nor any of the 9 `list_carts` returns
for that buyer. Any holder can redeem it; **who then owns the cart is unresolved** — open, not asserted.
**O4 the anon→auth merge runs at L7 restore, not at L4b `update_cart`** — no `update_cart` was involved, so
scenario 13 as modelled exercises a path the buyer does not hit.
**O5 D1 is WORSE than recorded — one payload carries the field twice, at two paths, with two types**
(corrected by the orchestrator against the saved payload; the lane's original "refuted, they now agree"
was reading only the nested path). `get_store_capabilities` returns **both** `ucp.payment_handlers = {}`
(empty object, matching `/.well-known/ucp` on both hosts) **and** top-level `payment_handlers = [3]`
(`hosted_checkout` available; `native_card`, `google_pay` `not_available`). So the self-contradiction is
*inside a single response*, not merely across two endpoints as D1 says. Restate D1; do not close it.
**O6 D6 confirmed, wider.** `create_checkout` → `{ucp, checkout, messages}` (no url) · `handoff_checkout` →
`{result, last_checkout, next_step_after_payment}`, url at `result.checkout.continue_url` ·
`checkout_and_handoff` → `{ok, cart_id, buyer_id, checkout, handoff, continue_url, next_step_after_payment}`,
url at **top level** *and* `handoff.checkout.continue_url`. One path read uniformly → `undefined` from two.
**O7 `create_cart` reports success on a line it did not add.** Configurable SKU `AGENT-TEST-CFG-020` →
`status:"success"`, empty `line_items`, failure only in `messages[]` (`CONFIGURATION_SECTION_REQUIRED`).
An all-zeros `product_id` → success, empty cart, **no message at all**. The agent learns only at handoff,
and `search_products` calls that SKU `product_type:"Physical"`, so it is not foreseeable.
**O8 `continue_url` is not signed (1d DRIFT)** — 43 base64url chars = 256-bit opaque random, no JWT, no
signature segment, resolved by cache lookup. The AC word "signed" is factually wrong.
**O9 no agent-attribution artifact exists pre-payment (1d DRIFT).** Across all 14 fields the restored cart
carries, none names UCP or the agent — no dynamic property, comment or line-item tag; `organization_id` is
ordinary B2B scoping. **An authed UCP cart is indistinguishable from a human's.**
**O10 two envelope vocabularies ship together** — discovery `2026-04-08`/`com.virtocommerce.ucp.*`, every
tool response `1.0`/`dev.ucp.shopping.*`.
**O11 SUPERSEDED for the dedicated fixtures (orchestrator, after 3-cases).** This lane ran CONCURRENTLY with the seeding lane, so its 8-SKU sample predates the org-contract fixture and did not include it. Re-measured live twice since — by the orchestrator and independently by the 3-cases verifier on a third lane — the contract product `UCP_CONTRACT_PRODUCT` reads **29.99 anonymous vs 11.11 contracted** (delta 18.88), the control `UCP_CONTRACT_CONTROL_PRODUCT` reads **3.49 in both** contexts, and `UCP_ORG_ONLY_PRODUCT` is **invisible anonymously, 44.44 to the org**. **Sc.15/16 are DECIDABLE and now PASS.** O11 stays on the record because it was true of the SKUs it sampled at the time it sampled them — and the 3-of-8 priced at $0.00 is still a live warning that an arbitrary SKU makes a vacuous price assertion.
**O11 org price == anonymous price, 8 of 8 SKUs.** Read back through the **authenticated UCP path**
(org-scoped bearer, `aud=/ucp/mcp`, `search_products` as the buyer) against the same query anonymously —
*not* the admin pricelists route. Confirms the model's FIXTURE-GAP: **Sc.15/16 stay UNDECIDABLE**. Also 3 of
8 SKUs price at `$0.00`, which would make a price assertion vacuous.
**O12 authed `create_cart` is an upsert into the buyer's `default` cart, and is not idempotent.** Two calls,
same SKU → same cart id `be8ace81…`, quantity 3 → 4; the agent's item then shows in the human's own `/cart`.
An agent "starting fresh" appends to what the buyer already has.
**O13 one fixture account ⇒ one shared `default` cart across lanes.** `list_carts` as John returned
`ucp-r1-probe` (not this lane's) plus 8 more from earlier runs; nothing sweeps them. **Flagging to the
orchestrator:** the chrome lane and this lane mutate the same `default` cart (test-data.md DISPOSABLE
FIXTURES r4). Named UCP carts need an `AGENT-TEST-` prefix plus teardown.
**O14 the agent's `shipping_address` does not reach the buyer's cart, and the buyer must still finish.** The
agent handed `123 Market St, Los Angeles CA`; the cart shows the buyer's own `456 QA Avenue, New York`.
Delivery and payment method unselected, **"Place order" disabled** — line items, not a ready-to-pay checkout.
