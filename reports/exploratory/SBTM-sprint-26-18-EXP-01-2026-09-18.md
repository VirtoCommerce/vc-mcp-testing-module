## Oracle Feedback

- Rows 1–3 return `Oracle ref: NONE`. Proposals routed to `/qa-review-oracles` (`ba-system-analyzer` is the sole writer — **no oracle file was edited**):
  - **Proposed BL-UI candidate:** *"A focus indicator's colour is derived from the active theme preset, never a fixed literal."* Distinct from BL-UI-001..006 (all geometry) and from the existing contrast invariant (which grades a measured ratio, not the token's provenance). The Red/Coffee a11y gating cannot catch this class, because a non-themed token is identical on every preset.
  - **Proposed ECL `[THEORETICAL]` pattern:** *"UI-kit change ships with a deprecation note and no consumer migration → new API is live but unexercised; a regression in it is invisible until a fork adopts it."* Observed twice this sprint (#2459 `headAttrs`, #2470 `--vc-button-text-transform`).

## Bugs Found

None filed. One **Low/advisory** observation (net-new #1): ring-vs-filled-control edge is 1.25:1 on the Red preset. Not filed as a WCAG 1.4.11 failure because the ring's outer edge meets 3:1 against the page surface (3.68:1) with `outline-offset: 2px`, which is the commonly accepted reading of "adjacent colours". The **defect-shaped** part is the hardcoded token, which is a design-system issue, not a measured threshold breach — escalating as a proposal rather than a bug is deliberate. No Critical found; no stop-and-report triggered.

## Risk Areas

- **Non-themed design tokens generally.** `--color-ring` proves a literal can sit on `:root` beside real preset tokens. Whatever else is hardcoded there is invisible to preset-based a11y gating.
- **UI-kit PRs that touch no consumer.** Both #2459 and #2470 shipped contract/visual changes with zero consumer edits; #2470's own PR body flags "visual breaking change for all sm–lg buttons app-wide". Corpus has no UI-kit component suite to absorb that (charter's C1).
- **Environment provenance.** The whole sprint is being validated on an unmerged-PR build carrying PR #2467's auth rewrite.
