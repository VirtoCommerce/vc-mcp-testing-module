# Self-diagnostics — design rationale and evolution

> **Moved verbatim from `CLAUDE.md` §Project Overview on 2026-09-08** (PR 2 of the agentic-system audit). This is the *why* behind the `vc-fix` self-diagnostics subsystem (VCST-5475–5479, 5509, 5582). Never loaded into an agent context. The operative contract lives in `plugins/vc-fix/skills/vc-self-check/` and `knowledge/diagnostics/skill-expectations.md`.

**Self-diagnostics — capture, judgement and surfacing are THREE separate layers (VCST-5582 H).** The collector **records that something happened and is forbidden from deciding whether it matters**; `/vc-self-check` assigns severity; the `Stop` hook chooses only tone and timing. This inverts the original design, where `emitSpan`'s non-success test was simultaneously the *retention*, *analysis-scope* and *surfacing* decision (`state.flagged[]` was the only thing the diagnostician read), so any signal the deterministic classifier did not recognise at span close **ceased to exist** — a real `/project-init` run printed a **WARN** in its own readiness table (the Azure Bug field contract was never scanned: HTTP 400 → stderr → exit 0) and self-diagnosed `no plugin issues detected` with `spanCounts:{success:31}`, `flagged:[]`. Every anomaly signal, however minor, is now a durable **`type:"obs"` record** with **no severity/verdict field** — closed `class` vocabulary, slugified `subject`, taxonomy `code`, aggregated by signature (first sighting appends, later ones bump `count`; caps announce themselves as `capture_truncated`, never truncate silently). New capture sources: the transcript's `toolUseResult` sidecar (**stderr on an exit-0 tool**, `interrupted`, `Exit code N`), self-labelled degradation prose (`unverified defaults`, `falling back to`) in stdout **and** stderr, every non-PASS row of `verify-access.mjs`'s readiness table + every failed scan in `discover-tracker.mjs` (via the collector's new **`obs` subcommand**, `skills/project-init/lib/diag-obs.mjs`), the written profile's SHAPE (`skills/project-init/assert-profile.mjs`), signals on spans that end `success`/`recovered`, sub-agent **sidechain** errors (aggregate-only), and the collector's own health. Two hard invariants make the original failure unrepresentable: `verdict:"clean"` requires `observations.total === 0 && flaggedTotal === 0 && !scanErrors`, and any `self_reported_warn`/`_fail` forces at least `attention`. `decision.verdict` (`clean`/`observed`/`attention`/`degraded-collector`) now describes the **run** and is derived from counts alone; `surfaceDecision`/`suppressReason` describe the **UI choice** — conflating them is how a `failed` span once landed in a record that called itself `clean` (two such sessions are still on disk). The status line has **three** states so the hook can stay quiet without ever saying "clean" while observations exist. Surfacing is bounded by a **HARD routing class set** (data, mirrored in the oracle §1e) plus per-signature dedup — everything outside it is still recorded, still counted, still analysed. The set is `self_reported_fail` · `degraded_artifact` · `script_exit_nonzero` **from a plugin-owned script only** (`obs.pluginOwned` — anchored to the installed plugin root: a `$CLAUDE_PLUGIN_ROOT/{hooks,skills,scripts}/…` reference or an absolute path under `pluginRoot()`, **NOT** a bare `PLUGIN_SCRIPT_RE` dir-name match, which `opSubject` still uses for the `subject` label; so a client's own failing `node ./scripts/build.mjs` under its own `scripts/` is recorded but never arms the plugin's diagnostician) — plus, outside the observation stream, a flagged span, a 👎, and a **grown occurrence count** (`obsSurfacedCount` records the count a signature routed AT, so a recurrence re-qualifies instead of being silenced for the session; §1f rule 5). `self_reported_warn`, `http_non2xx` and `collector_contention` were **demoted out of routing** — the old set fired on essentially any new signal, so a run whose command span ended `recovered`, whose deliverable landed, and whose findings were all S2/S3 friction still cost the operator a whole extra turn; they still forbid the word "clean" (a verdict rule, not a routing one) and are still diagnosed on the next `/vc-self-check`. A turn now emits **ONE info line and at most ONE question**: the cleanup **question was removed** (the reproduction asked verdict + delivery offer + a 3-option cleanup prompt at once, so the delivery offer had to be re-asked later), because the 24 h age-cap already reclaims leftovers unprompted — the artifact count now rides the info line as data, not a decision. Deletion now requires the *analyze* step: a session holding an un-diagnosed finding survives the 24 h age-cap and `purge-inactive` (`--force` overrides). Judgement rubric + correlation rules: `knowledge/diagnostics/skill-expectations.md` §1e/§1f.

**Self-diagnostics subsystem** (VCST-5475–5479, evolved into a client→vendor feedback loop by VCST-5509) — a two-tier way for a client-installed `vc-fix` to observe whether its OWN skills ran correctly and (opt-in) report quality issues back to VirtoCommerce, without ever mutating the client install or leaking client code. **Tier A** (passive, **opt-in** — captures only when `project-profile.json` sets `selfDiagnostics: true`, default off): `hooks/session-telemetry.mjs` wired via `hooks/hooks.json` — `SessionStart`→init, `UserPromptSubmit`→prompt (`/vc-feedback`), `PostToolUse[Skill]`→record, `SubagentStop`→agentstop, `Stop`→finalize. It reads the session transcript delta at each skill boundary + Stop and records deterministic, outcome-classified span signals (tool errors, denied permissions, hook failures, STOP/BAIL markers) to `<outputRoot>/.vc-fix/diagnostics/<session_id>.jsonl` (`outputRoot = VC_FIX_HOME || cwd`, per `paths.mjs` — NEVER the plugin dir; `.vc-fix/` is gitignored). Secrets are redacted; it never throws/blocks. **Tier B** (on-demand): `/vc-self-check` (`skills/vc-self-check/`) reads the telemetry + transcript against the oracle `knowledge/diagnostics/skill-expectations.md` (per-skill expected phases/gates + S0–S3 rubric) **via the `self-check-diagnostician` subagent, which returns a validated finding STRUCT** — it writes **NO local report file** (the old `DIAG-*.md`/`.json` was removed in the PR #172 rework; the oracle/jsonl/transcript never enter the main conversation). The `Stop` finalize runs `/vc-self-check` **silently via a tail-trigger** (`{decision:"block"}`, no `AskUserQuestion` modal) **only when the Tier-1 classifier flagged ≥1 span** (outcome `failed`/`degraded`/`silent_suspect`) or a `/vc-feedback` 👎 was recorded that session; a clean run prints one `vc-fix self-check: no plugin issues detected` line, and a plain development session with no plugin skill never triggers it (opt out with `VC_FIX_DIAG_CONSENT=off`; a session whose transcript scan errored is reported `degraded-collector`, not clean). It is model-invocable (no `disable-model-invocation`) so the tail-trigger can auto-run it, but never auto-triggers unprompted — recursion/re-nag is blocked by the `selfCheckSeen` one-shot guard + per-signature dedup + the collector dropping its own `vc-self-check` spans. `skills/vc-self-check/deliver.mjs` (`/vc-self-check deliver`, run by the `self-check-deliverer` subagent) turns the validated finding struct into a consent-gated contribution to `VirtoCommerce/vc-mcp-testing-module`, routed by GitHub-token rights via `probe-lib.mjs` — **two routes only, `issue` / `local`**: any authenticated token with issue rights (push/maintain/admin included) files a **GitHub Issue**; only a missing token, a probe that fails twice, or read scopes carrying neither `repo` nor `public_repo` stay local. The former `pr`/`fork-pr` routes were **removed**: both were hand-offs that printed `git`/`gh` commands and sent nothing, so the MORE rights a token had the LESS was delivered (a `maintain` token produced `sent: false, handoff: true` while an issues-only token auto-filed) — and a telemetry report is not a code change, so it never needed a PR. A transient probe failure is **retried once** (`probeWithRetry`) before falling back to `local`, and the `reason` says so; everything operator-actionable also travels as a `nextSteps[]` field in `--json`. **§2a client-code containment is enforced by a default-deny CLOSED SCHEMA, not a denylist:** the outbound artifact is built ONLY from a validated `UpstreamSignal` struct (`skills/vc-self-check/upstream-reduce.mjs` → `reduce`/`validateUpstream`/`fingerprintStruct`; spec `knowledge/diagnostics/upstream-schema.md` + ADR `adr-upstream-default-deny.md`) whose every field is a closed-vocabulary enum or number — skill/**subject**/**blockedDeliverable**/verdict/severity/outcome/signal-class/struggle/error-**taxonomy-code**/tool-family/repo-**kind**/counts, ZERO free-text fields. **Schema v2** added `subject` (a closed `SUBJECTS` enum naming WHICH operation misbehaved — `ado_create_workitem`, `browser_login`, `github_search_issues`, …) and `blockedDeliverable`, because a v1 row read `other | BROKEN | S1 | …` and could not distinguish an Azure-Boards field-contract blocker from a credential-handoff gap; a row now renders `S1 · qa-bug · ado_create_workitem · blocked`. `subject` is a **mapping, never an echo** (`subjectEnum`, `_`-boundary-delimited markers so a client repo name containing e.g. "checkout" cannot steer the bucket). **Input is a validated struct, not a parsed report (PR #172 rework).** `deliver` receives the finding STRUCT the `self-check-diagnostician` subagent produced (on stdin / `--input <file>`), re-validated by `validateUpstream`; the old `--diag` + DIAG-markdown-table + sidecar-`DIAG-<sid>-<ts>.json` source-precedence chain is **GONE** — parsing a human-written `.md` for a closed vocabulary was the shared root cause of the header-backtick and `skill: other` defects, fixed by deletion. `reduce()` (the pure reducer the tests exercise) reads ONLY the structured collector jsonl — span records + **`type:"obs"` observation records** + feedback verdicts; the diagnostician's free-text fields (`signal`/`rootcause`/`fix`) and `/vc-feedback` prose NEVER enter the upstream path (feedback travels as 👍/👎 counts only), error TEXT is classified locally to a code (only the code travels), and repo/module/org NAMES are never sent — so the client-data-leak class that recurred across three review rounds is impossible by TYPE. `redact()` (shared `hooks/redact.mjs` secret rules) still scrubs the local persist path; the former free-text client-shape scrubbers (`scrubText`/`isClientSpecific`/`containsClientShape`) were **removed as dead code** (PR #143 review round 2) — with an enum-only upstream artifact there is nothing free-text to scrub, so the closed schema is the sole upstream guard. Local diagnostics are **ephemeral** — the lifecycle is log → analyze → contribute → **delete**: on a successful Issue delivery (`--confirm`, or a dedup already upstream) `deliver` removes the processed session's own artifacts (`<sid>.jsonl` + `<sid>.state.json`; that session only, never others; the `<sid>.surfaced.json` tombstone is deliberately KEPT so a rebuilt session never re-nags an already-delivered defect; `--keep` retains). The `local` route (nothing sent) deletes nothing — it prints the ready `--purge` cleanup command. **Canonical copy: `plugins/vc-fix/`.** The **self-diagnostics subsystem is now kept in sync across both surfaces** (PR #143 R2): `hooks/redact.mjs`, `hooks/session-telemetry.mjs`, `skills/vc-self-check/deliver.mjs`, and `skills/vc-self-check/upstream-reduce.mjs` are **byte-identical** in `plugins/vc-fix/` and `.claude/`, so the hardened secret redaction + the default-deny closed-schema upstream path ship on BOTH — the client-data-leak class is closed on both, not just the distributed plugin. The `.claude/` mirror may still lag on **non-self-diagnostics** surface (e.g. no dedicated `/vc-feedback` command md — the `session-telemetry.mjs prompt` handler is present and wired, a shorter `skill-expectations.md`); those are prose/UX, not a containment gap. Self-diagnostics changes land in `plugins/vc-fix/` first and are copied to the mirror in the same change.
