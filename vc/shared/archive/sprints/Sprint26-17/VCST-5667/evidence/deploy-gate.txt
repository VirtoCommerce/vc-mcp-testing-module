## 4. What the unit tests DO and DO NOT prove  (verified independently, not taken on trust)
`VcInput` sets `inheritAttrs: false` and binds leftover attrs to its root <div>, so a plain
attribute would land on the wrapper and be silently ignored by the browser. The fix therefore
passes `autocomplete` as a PROP.

But the suites stub VcInput as a bare input, e.g.
  framework/shell/components/change-password/change-password.test.ts:40-41
    VcInput: { template: '<input data-stub="VcInput" />' }
In that stub, attributes fall through to the <input> automatically. The assertion
  w.findAll("input").map(i => i.attributes("autocomplete"))
therefore passes whether the token is correctly prop-bound OR stranded on the wrapper.

=> The unit tests pin the token VALUES and their ORDER. They cannot prove the token reaches
   the native <input> in a real render. Only a live DOM read can, which is why the live pass
   (and the author's own live pass) is load-bearing here rather than decorative.
