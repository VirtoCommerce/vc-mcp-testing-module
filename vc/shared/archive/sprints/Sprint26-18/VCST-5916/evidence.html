Points history now names its mission grants

Verified 2 follow-ups · 0 defects filed

The Operation column rendered empty for all 69 mission-granted ledger rows on the fixture account. Both halves of the fix are live and the blank cells are gone: the xAPI resolver now returns a typed object and the storefront maps it to a localized label. Verified against the pinned pre-release builds of both open PRs.

Root cause, both halves

LoadLoyaltyObject()'s objectType switch handled only CustomerOrder and ApplicationUser, so "LoyaltyMissionProgress" fell to a null-returning default arm. Downstream, getOperation() in points-history.vue ended with return log.object?.type — undefined for a null object, which Vue renders as an empty string. Platform REST had the attribution all along; only the read projection lost it.
