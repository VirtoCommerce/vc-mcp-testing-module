The bug and its root cause

In a mixed cart (one cash line + one loyalty/points line), unticking the cash line — leaving it in the cart — left PLACE ORDER enabled with no warning, so a points-only order was placeable.

LoyaltyCartValidator rule 2 derived hasPointProducts from the selection-aware cart.CartTotals but hasCashProducts from the selection-blind cart.Items. A deselected cash line therefore still satisfied hasCashProducts, so the guard could never fire while any cash line existed at all. 

// vc-module-loyalty · Validators/LoyaltyCartValidator.cs — rule 2's cash operand
- var hasCashProducts = cart.Items?.Any(x => !x.Currency.EqualsIgnoreCase(loyaltyCurrencyCode)) == true;
+ var hasCashProducts = cartValidationContext.CartAggregate.SelectedLineItems.Any(x => !x.Currency.EqualsIgnoreCase(loyaltyCurrencyCode));

Notes — pre-existing, none caused by this PR

  1. A11y (Medium). Every line-item checkbox is labelled "Toggle vendor select", identical to the vendor group's select-all. A screen-reader user cannot tell which product a checkbox controls — directly relevant here, since deselecting a specific line is the action under test. WCAG 1.3.1 / 2.4.6.
  2. UX (Low). ALL_LINE_ITEMS_UNSELECTED renders no message at all — PLACE ORDER is disabled with no explanation. The storefront's error-code→i18n map covers the loyalty codes but not this one.
  3. Test cases. The committed MCO-E2E-008 Steps untick the cash line before setting delivery/payment, so they never establish PLACE ORDER was enabled first; this run used the corrected ordering. Both new cases now pass and are eligible to leave Automation_Status = Draft and drop their EXPECTED-RED until VCST-5657 notes.
  4. Fixture drift (carried over). LOYALTY_NOBAL_USER holds ~1,044 PTS, so insufficient-balance cases silently test nothing — needs a re-seed.
  5. Behaviour change. Storefront loyalty validation is now pre-emptive on /cart (inline message + disabled control) rather than a toast at placement. Older loyalty cases written against the toast expectation will false-FAIL.
