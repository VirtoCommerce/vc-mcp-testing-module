vc-tools plugin · Flagship

The plugin now grades its own homework.

A two-tier self-diagnostics subsystem so a customer-installed plugin can tell whether its own skills ran correctly — and, opt-in, report quality issues back to us.

  • Passive telemetry — records each skill's phases, gates, and anomalies to a local, gitignored log. Never blocks a tool, never throws, secrets redacted.
  • On-demand /vc-self-check — reads that log against an expectations oracle and emits a per-skill verdict: OK / DEGRADED / BROKEN, with a proposed fix.
  • Contribution, contained — a scrubbed, consent-gated issue or PR back to VirtoCommerce. It's opt-in, one-shot, and ephemeral — log, analyze, contribute, delete.

vc-tools plugin · Flagship

One plugin, any deployment — ours or a customer's.

The plugin now onboards onto a customer's stack and routes each fix to the right place, behind a hard security invariant.

  • Tracker & host adapters — Jira or Azure Boards; GitHub or Azure Repos. Bugs file to the customer's tracker in its native shape.
  • Ownership-aware routing — client custom code → a PR on the client's host; a genuine platform bug → a fork-PR contributed upstream to VirtoCommerce.
  • Client-code containment — a hard invariant: client source never leaves the client's project. Enforced at routing, at review, and in the dev team.
  • Onboarding that survives upgrades — /project-init --check migrates a stale profile to the current schema, so no re-onboarding after an update.

Agentic project · New command

/qa-deploy-pr — deploy a whole change at once.

A change often spreads artifacts across several repos — modules, Platform, the storefront theme. Stitching them into the deploy manifest by hand blocked verification. Now it's one command.

  • Gathers every fresh artifact — resolves the ticket's linked PRs across all repos, then picks up each PR's latest prerelease build.
  • One manifest update — repins modules, Platform, and theme together in a single deploy change instead of several hand edits.
  • Safe by default — dry-run diff first; apply opens one gated deploy PR; verify confirms it landed live.
  • Unblocks the next step — PR testing and fix-verification can finally run against the change. Never auto-merges.
Before: a manual, multi-repo chore that stalled verification. After: one command, one PR, verified live.

Agentic project · New command

Our business-logic knowledge base now audits itself.

/qa-review-bl triangulates each business rule against three independent sources and corrects drift automatically — gated by evidence, not by blind trust.

  • Three-source triangulation — official docs, live storefront behavior, and platform source code, checked per rule.
  • Gated auto-apply — confirmed corrections are written straight to the oracle; anything contradictory or ungrounded is routed to a human-review proposal instead.
  • Runs on every lifecycle — it fires automatically for the rules a test run touches, so the knowledge base can't quietly go stale.

Agentic project · Hotfix lifecycle

Shipping a hotfix, end to end.

Backporting a fix to a frozen stable line used to be a manual cherry-pick-and-deploy chore across bundles and environments. Three commands now chain it: discover → release → deliver.

  • Discover — /qa-bundle-check — points a frozen stable bundle at GitHub and flags every pinned module / Platform / Theme with a newer same-line patch waiting; never a newer minor. Each hotfix traces to its PR and tracker task.
  • Release — /qa-hotfix — resolves the task → its merged, shipped fix commit, checks a fix-shape safety gate (single module, no dependency bump), then per bundle cherry-picks onto the support/<X.Y> line and triggers the repo's "Release hotfix" workflow.
  • Deliver + verify — /qa-hotfix-check — bumps the deployed stable and regression envs, waits for the deploy to go green and the platform to report the new version, verifies the fix live, updates the tracker, and bumps the stable bundles.
  • Gated, never auto-merges — read-only dry-run first, every write gated; it STOPs cleanly when there's no support branch or the fix hasn't shipped yet.
Before: a manual, multi-bundle backport that stalled patch delivery. After: discover → release → deliver, gated at every write, verified live.

Agentic project · Depth

The everyday pipelines got smarter.

Where daily leverage compounds — running, understanding, and feeding the suites.

/qa-regression Live dashboard

Per-case status flips PASS / FAIL live as the run proceeds, and each real failure writes an isolated trace — network, console, and stack — so we see problems as they happen, not after.

/qa-triage-results Why it failed

Classifies every failure as a real product bug vs a test defect vs flake or environment, verifies the real ones live, and routes test-defect fixes automatically — turning a red run into an action list.

sitemap + data Self-refreshing inputs

The storefront sitemap now refreshes on a per-sprint cadence, and new seeders and RBAC fixtures keep test data current against the live product.

Agentic project · The quality bar

Every assertion now has to earn its place.

Trustworthy tests come from grounded assertions and honest data — we made both structural.

Assertion provenance gate

Every generated assertion is tagged with its source — a spec, a business rule, docs, or a live observation. Ungrounded assertions are blocked from promotion, and a new feature must be grounded live before it ships into a suite.

WCAG 2.2 AA accessibility

The accessibility audit was sharpened for WCAG 2.2, its scanner refreshed, and a real widget audit filed. The scan is allow-listed as a safe, read-only interaction so it runs cleanly.

Env-agnostic test data

Every environment owns its own data aliases and no runtime IDs live in committed files, so a suite can never resolve another environment's data by accident.

Test-data engineer, end to end

The agent now owns the whole flow — it authors seeders and runs them live against a non-prod environment with drift-guard validation, not just writes the code.

What we're proud of

We shipped a QA platform that carries more of its own weight.

Three things worth saying out loud:

The plugin

Trustworthy with a customer

Client-deployment support plus a hard client-code-containment rule means we can put this in front of a paying customer without risking their code leaking upstream.

The loop

It tells us when it's wrong

Self-diagnostics, live traces, and a self-auditing knowledge base close the loop the old way never could — a degraded skill or a stale rule surfaces itself instead of silently passing.
