The Active column on the storefront's company members roster is derived from the CONTACT's status, not from the security account's state, and the two are different fields that happen to share a name. The query the page issues selects the contact's status together with securityAccounts{id,email,roles} and requests NO lock or account-status field at all, so no account state can reach the column by any path - this is a missing projection, not a stale cache. Admin carries two independent per-account fields that the roster never sees: Status (observed values Approved, Locked, PendingApproval) and a derived Locked state (Unlocked/Locked). A contact whose account is Locked, and a contact whose account is still PendingApproval because the invitation was never completed, both keep contact status Approved and therefore both render as Active with the green tick. The roster can only ever show Active for a member that exists; to learn whether a colleague can actually sign in, read the account blade under Security > Users, never the storefront roster.
