# Skills & Commands Reference

## Slash Commands (31) — `commands/`

All commands have YAML frontmatter with `description`, `argument-hint`, and invocation control. Commands with side effects use `disable-model-invocation: true` to prevent accidental auto-triggering.

**31 live commands = 31 `commands/*.md` files.** The table below has 31 rows, which is a coincidence of two offsetting exceptions: it carries the struck-through `/qa-sync-tests` **tombstone** (no command file — kept deliberately so an old reference resolves to its replacement; invoking it does nothing), and it omits a row for `/qa-review-bl`, which *does* have a file but is documented as an alias inside the `/qa-review-oracles` row.

| `/qa-test` | `VCST-XXXX \| feature \| PR #N` | No | Test a JIRA ticket, feature, or PR. **Tiered lifecycle** — Step `1a` routes on **two axes** per [`ticket-routing.md`](../knowledge/execution/ticket-routing.md): first the **FLOW** by ticket **type × status** (a fix-ready **Bug** → runs `/qa-verify-fix` RED→GREEN **inline**; a hotfix-status Bug → `/qa-hotfix-check`; a Sub-task → inherit parent; else **`feature-test`**), then, for `feature-test`, a **FAST** path (P2–P3 single-layer bug/tweak/tech-task — **a checklist and nothing else**: `1a`+`1b` → Artifact-B checklist → one execution agent + the critical-case regression → `5a`–`5f`; **no `1c`/`1d` agents, no `1e` Test Model, no archetype/UIP/`VC-*` sweeps, no case authoring, no `5g`, no verifier**) or a **FULL** path (feature/Story/P0–P1/cross-layer/unclear: `1c ‖ 1d` concurrent + a **mandatory Test Model** + full authoring + the independent verifiers + `5g`). *When in doubt → FULL.* A FAST run adds no regression coverage (`/qa-test-lifecycle` is the way in), so its checklist is the only durable record — hence a committed file. The independent verifier (fresh `qa-lead-orchestrator` in §Verifier Mode; never the step's doer; re-derives via `suites:review`/`td:validate`/`compute-metrics` + a live re-check on a different lane) runs **only at the three hard-STOP gates (Step 3, Step 5b, Step 5g), FULL path only**; REJECT → reason + fix → re-verify **once (1 round), then STOP**. Ends at an independently-ratified Feature Release Gate GO/NO-GO. **The Test Model (Step 1e) is a fault model, not a scenario list** — a condition space, an explicit reduction rationale, and a matrix whose every row carries cell · defect hypothesis · archetype · technique · oracle, plus a Mermaid user-flow diagram and (when the ticket has one) a DoD checklist. Enforced by **two** deterministic gates: Step `1e-plan` emits the matrix as an authoring plan JSON and `npm run tc:scaffold --check` rejects a planned row that cannot name its observable, its customer-visible defect (null-hypothesis phrasings refused by name) and why that defect is plausible here — the §6d cull moved to before the case is written; then the appender rejects a new suite row lacking `Archetype:`/`Technique:` stamps. `tc:scaffold` also derives ten of the fifteen columns and expands the `state-stress`/`uip`/`toggle`/`date-range` sweeps from the markdown that owns each table (read at run time). **Step 3b fans authoring out one batch per EXECUTION SURFACE** (surface ≙ CSV file, so batches are file-disjoint and the one-author-per-CSV rule holds): `npm run tc:alloc` hands each batch a disjoint ID block before dispatch, the orchestrator owns the `[JOURNEY]` case and the matrix-cell assignment, batches self-lint staged CSVs in the scratchpad, and the orchestrator appends serially + runs `suites:sync` once. **Step 3 reuses the same skills `/qa-test-lifecycle` Phases 3–4 run** (`/qa-test-cases-generator` + `/qa-review-tests` + `/qa-generate-data`; not the full lifecycle command) and **appends new cases into `regression/suites/` as `Draft`**; Step 4's regression executes them via `/qa-regression <ids> --cases critical --also-ids <new case IDs>` — **case-scoped, not suite-scoped**, with the suite list bounded by `regression:select --target 40` so the run fits a **40-minute window** (Critical is ~22% of the corpus; `--also-ids` carries the new Draft rows in at any priority, and the runner does not skip Draft — the "latest test"; its own FAILs are triaged via `/qa-triage-results --fix` at Step 5a rather than ad hoc), then 5g (last, non-blocking) flips the eligible ones **`Draft → Automated`** (green under the automated runner) / `Reviewed` (checklist-only), reverting non-promotable rows — verifier-ratified + user-confirmed, in-run. **Step `1b` item 2b derives the ticket's LAYER** (`storefront`/`admin-spa`/`api`/`module`/`platform`/`cross-layer`, from the PR diff + the suite manifest, never asked and never defaulted — an unresolved layer is a loud `layer-unresolved`), and 5f records it plus the `release` block in `summary.json` and then **points** at `/ba-analyze docs release <ticket-key>`. **`5h` then publishes the ordinary product documentation**: the §3/§4/§5 guides for the surface the ticket moved, written to `reports/ba/`, and posted as **ONE tracker comment with a section per audience** via `/ba-analyze docs ticket <ticket-key> --publish` — both paths, after TESTED, ask before posting, and refuse (`verdict-not-pass` · `layer-unresolved` · `not-deployed` · `not-user-visible`) rather than pad. It is **not** a release note: no version literals, and the layer-derived audience is a floor rather than the only one (`knowledge/ba/virto-doc-style.md` §10). A pointer, never a trigger: `/ba-analyze` is `disable-model-invocation: true`. **`--iterate`** (default `--max-rounds 2`) drives a bounded **test → fix → re-test loop** in Step 5k: a FAIL auto-runs `/qa-fix` (G0–G7, never merges) → `/qa-deploy-pr` the **prerelease** (confirm each deploy, no merge) → re-run the failed cases (their **own** `--ids` run) + the change-scoped regression **re-scoped to the fix's diff**, up to the cap, then STOP for a human; PASS exits to the Feature Release Gate. **It re-persists as well as re-runs:** per round it files new bugs (one this run already filed is **CARRIED** — kept IN-SCOPE, not re-filed, not relabelled PRE-EXISTING), posts a short round delta, rewrites `summary.json` with the round appended to `iterations.per_round[]`, and **appends** to the checklist; the release gate, the full comment, the transition and promotion fire **once, at loop exit**, so one QA-Complete comment and one transition per run whatever the round count. Per-round table + reasons: `skills/qa-test/modes.md` §5k. Merge + release stay the human's (§2 triple guard). **Epic-aware:** Step 1a resolves a story's **parent Epic** (goal + sibling statuses) and adds integration coverage vs Done siblings; **`--epic <EPIC-KEY>`** tests a parent Epic's child stories **in series** (dependency-ordered, state carried story→story, a final cross-story E2E) and emits per-story verdicts + an **Epic roll-up** GO/NO-GO |

## Usage

`/qa-smoke`, `/qa-test VCST-1234`, `/qa-test-lifecycle PR #123`, `/qa-storybook Button`, `/vc-docs dynamic properties`, or use agents directly: `"Use qa-frontend-expert to test checkout"`

**Frontmatter fields:** `description` (shown in `/` menu with `[Category]` tag), `argument-hint` (autocomplete hint), `disable-model-invocation: true` (prevents Claude from auto-triggering). Only read-only, no-side-effect commands/skills allow model invocation: `/qa-status`, `/qa-env-check`, `/vc-docs`, plus the two reference-only methodology skills `/qa-evidence` and `/qa-sbtm` (both surface policy/methodology text only — no browser, writes, or external calls). `/qa-accessibility` is also model-invocable: an a11y audit is read-only against the live site (axe-core/Lighthouse/keyboard walk, no mutations) and only writes a bug report when a violation is actually confirmed, so it can safely auto-run in response to an accessibility-related request without requiring the literal `/qa-accessibility` invocation. `/vc-self-check` is the one deliberate exception that is model-invocable **despite** writing a local `DIAG-*.md`: it must be auto-runnable by the `Stop` **silent tail-trigger** (`{decision:"block"}` when a span was flagged), so it carries no `disable-model-invocation`; unprompted auto-triggering is instead ruled out by its description + the `selfCheckSeen`/per-signature-span-dedup recursion guards.
